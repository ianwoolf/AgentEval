# Upgrade to 2.3.3

Published images:
- ianwoolf/evaluation-ui:2.3.3
- ianwoolf/evaluation-worker:2.3.3 (API and dynamically created Runner)
- ianwoolf/evaluation-mock-guardrail:2.3.3

Run commands from the AgentEval repository root, against the intended cluster. These examples use namespace evaluation and container names nginx/api/mock-guardrail.

## Kubernetes upgrade

1. Edit `evaluation-backend/deploy/kubernetes/guardrails.yaml` for the actual provider instances. Each instance needs id and full endpoint address; token_env refers to an environment variable injected from a Secret. The example intentionally registers the same test Mock endpoint for both existing providers for compatibility. Replace with actual endpoints for production. Apply the instance ConfigMap:

```bash
kubectl -n evaluation apply -f evaluation-backend/deploy/kubernetes/guardrails.yaml
```

2. Patch existing API config without replacing other settings:

```bash
kubectl -n evaluation patch configmap evaluation-api-config --type merge -p '{"data":{"EVAL_GUARDRAIL_REGISTRY":"/guardrails/guardrails.json","EVAL_WORKER_IMAGE":"ianwoolf/evaluation-worker:2.3.3"}}'
```

3. Apply the strategic merge Deployment patch. It sets the API image, adds the guardrails ConfigMap volume and read-only mount, and reuses Secret evaluation-mock-guardrail/key token. Other existing volumes/env/settings are preserved. API already needs envFrom evaluation-api-config, as in the existing deployment.

```bash
kubectl -n evaluation patch deployment evaluation-api --type strategic --patch-file docs/evaluation/releases/2.3.3-api-patch.json
kubectl -n evaluation set image deployment/evaluation-ui nginx=ianwoolf/evaluation-ui:2.3.3
kubectl -n evaluation set image deployment/evaluation-mock-guardrail mock-guardrail=ianwoolf/evaluation-mock-guardrail:2.3.3
kubectl -n evaluation rollout restart deployment/evaluation-api
kubectl -n evaluation rollout status deployment/evaluation-api --timeout=120s
kubectl -n evaluation rollout status deployment/evaluation-ui --timeout=120s
kubectl -n evaluation rollout status deployment/evaluation-mock-guardrail --timeout=120s
```

No ES migration, index recreation or Secret rotation is required. The existing token must be injected into both API and Mock. EVAL_MOCK_GUARDRAIL_ID on the Mock still controls its endpoint path ID. Once EVAL_GUARDRAIL_REGISTRY is present, API uses provider+instance from the JSON; legacy EVAL_MOCK_GUARDRAIL_ID/URL no longer select API connections.

Changing the JSON requires restarting the API (registry is cached per process). New Runner jobs use EVAL_WORKER_IMAGE; jobs already running keep their image and connection snapshot. UI port-forward may need restarting after rollout.

## Verification

```bash
kubectl -n evaluation get deployments -o wide
kubectl -n evaluation get configmap evaluation-api-config -o jsonpath='{.data.EVAL_WORKER_IMAGE}'
kubectl -n evaluation logs -f deployment/evaluation-mock-guardrail --since=10m
```

In UI Configure select provider -> configured instance. Trigger a saved evaluation. Mock logs should show guardrail.request.started/completed (or failed) with request_id, trace_id, HTTP status and duration; /health and /ready do not log requests. Credentials and input contents are omitted.

## Docker Compose

Use the updated backend Compose files, including config/guardrails.json. Update deployment .env:

```dotenv
EVAL_WORKER_IMAGE=ianwoolf/evaluation-worker:2.3.3
```

Set the UI deployment's existing image variable/reference to ianwoolf/evaluation-ui:2.3.3. If Mock is a separately deployed container, update its image to ianwoolf/evaluation-mock-guardrail:2.3.3 and ensure its network hostname matches guardrails.json.

Re-run backend deploy/docker-compose/init_secrets.py to create missing guardrail_token file; put the actual endpoint token in .secrets/guardrail_token. Existing files are not rotated by the script. API mounts it through EVAL_MOCK_GUARDRAIL_TOKEN_FILE; the Mock must receive the same token. Edit guardrails.json to point at reachable full Scan endpoints. Pull and recreate the affected Compose services. The supplied backend Compose does not automatically launch Mock Guardrail.
